# MCP Rooms: Персональный Агент-Ангел и Автономные Переговоры через MCP + SQLite

Интеграция встроенного чат-бота «Агент-Ангел» с реальным серверным бэкендом, постоянной базой данных SQLite на диске и автономным движком многоагентных переговоров в защищённых комнатах (Shared Rooms) по всем категориям объявлений (бизнес, товары, услуги, вакансии, дейтинг).

---

## User Review & Critical Decisions

> [!IMPORTANT]
> На основе ответов в интервью согласованы ключевые архитектурные решения:

- **База данных (Подтверждено):** Серверная SQLite БД с постоянным хранением на диске сервера (`data/mcp_rooms.db`), таблицами для объявлений (`listings`), комнат (`rooms`), сообщений (`messages`) и переговорных сессий (`negotiations`). Никаких фронтенд-заглушек или localStorage в качестве основного хранилища.
- **Поведение Агента-Ангела (Подтверждено):** Полная автономия агента при выполнении поручений. Агент принимает поручение на естественном языке, автономно вызывает MCP-инструменты (`search_listings`, `create_listing`, `join_room`, `send_message`), находит объявления контрагентов, вступает в переговоры с их агентами и прозрачно транслирует пользователю в UI ход каждого раунда переговоров.
- **Расширенный охват категорий:** Добавлены категории для бизнеса (`business`), вакансий/поиска работы (`jobs`), дейтинга/знакомств (`dating`) наряду с товарами (`things`), услугами (`services`), поездками (`rides`) и доставкой (`delivery`).

## 1. Overview & Core Concept

**«Агент-Ангел» (Angel Agent)** — это персональный ИИ-представитель пользователя в экосистеме MCP Rooms. Пользователь больше не тратит время на рутинный ручной поиск, фильтрацию сотен карточек и первичное выяснение условий у незнакомцев.

1. **Естественный ввод поручения:** Пользователь пишет боту свободную команду:
   - *«Найди партнёра в IT-стартап с опытом в маркетинге в Казани»*
   - *«Найди мастера на ремонт санузла до 40 000 руб, согласуй выезд на субботу»*
   - *«Хочу познакомиться с девушкой, которая любит походы и велопрогулки»*
2. **Автономное исполнение через MCP:**
   - Агент анализирует запрос и запускает поиск по каталогу (`search_listings`).
   - Если совпадения найдены, агент автоматически создаёт или входит в комнату переговоров (`join_room`).
   - Агент начинает диалог с агентом владельца карточки (`send_message`), проверяя требования, цены, локацию и график.
   - Если встречного предложения нет, агент предлагает пользователю опубликовать объявление-запрос (`create_listing`) и ждёт встречных откликов.
3. **Прозрачность и контроль:** Пользователь видит таймлайн автономных действий: «Поиск кандидатов → Вход в комнату #42 → Согласование условий с Агентом Мастера → Договорённость достигнута».

## 2. User Experience & Visual Design

### Ключевые пользовательские сценарии (User Flows)
1. **Поручение агенту в чате:**
   - Пользователь переходит во вкладку «AI Чат (Агент-Ангел)».
   - Вводит запрос на любом естественном языке.
   - Получает ответ агента с интерактивным статус-баром переговорного процесса:
     - 🔍 *Поиск релевантных карточек по категории и параметрам*
     - 🚪 *Создание/вход в защищённую переговорную комнату*
     - 💬 *Раунд переговоров между Агентом-Ангелом и Агентом контрагента*
     - 🤝 *Фиксация предварительного соглашения*
2. **Витрина переговоров (Negotiation Tracker):**
   - В правой части или внутри сообщения чата отображаются карточки активных переговоров: кто участник, статус («В процессе», «Договорились», «Отклонено»), прямая ссылка на комнату и последнее сообщение.
3. **Фильтрация и категории каталога:**
   - В каталоге и карточках появляются новые разделы: «Бизнес и стартапы», «Вакансии и резюме», «Знакомства и общение».

### Визуальный стиль и компоненты
- **Палитра:** Сохранение фирменного нейтрально-скандинавского стиля площадки: `--canvas: #fff`, `--surface: #f9f8f7`, `--line: #dedbd7`, синий акцент `--blue: #1868b3` и зелёный статус успеха `--green: #246744`.
- **Без визуального мусора (Anti-Slop):** Никаких бессмысленных фиолетовых градиентов или летающих эмодзи. Чёткие информативные блоки таймлайна переговоров с моноширинными метками параметров.

## 3. Key Product Decisions & Trade-Offs

- **Реальная SQLite БД на сервере:**
  - *Решение:* Используем встроенную легковесную библиотеку SQLite (или встроенный файловый модуль/better-sqlite3) с сохранением файла базы данных на диске сервера (`./data/mcp_rooms.db`).
  - *Почему:* Полная персистентность данных между перезапусками, готовность к моментальному деплою на любой Ubuntu VPS без необходимости поднимать отдельный контейнер PostgreSQL, отсутствие сетевых задержек.
- **Двусторонние переговоры между агентами:**
  - *Решение:* Серверный переговорный движок моделирует реакцию агента контрагента (Opponent Agent) на основе условий карточки (цена, локация, дедлайн, требования) и формирует логичный протокол диалога в комнате.
  - *Почему:* Обеспечивает мгновенный, реалистичный процесс переговоров, демонстрирующий главную ценность протокола MCP Rooms.

### Схема базы данных SQLite (`./data/mcp_rooms.db`)
1. **`listings`**: `id`, `owner`, `author_name`, `title`, `description`, `category`, `subcategory`, `kind`, `modes`, `locality`, `price_minor`, `currency`, `condition`, `status`, `created_at`, `updated_at`.
2. **`rooms`**: `id`, `listing_id`, `title`, `participants`, `status`, `created_at`, `updated_at`.
3. **`messages`**: `id`, `room_id`, `sender`, `role`, `text`, `tool_call`, `timestamp`.
4. **`negotiations`**: `id`, `room_id`, `listing_id`, `initiator_agent`, `target_agent`, `status`, `current_round`, `agreed_terms`, `created_at`, `updated_at`.
